# 陪玩师绩效与动态抽成模块需求文档

## 简介

陪玩师绩效与动态抽成模块是 GameLink 陪玩管理平台的核心激励管理功能,用于根据陪玩师的表现动态调整平台抽成比例。该模块通过多维度的绩效评估、灵活的抽成规则配置和智能的最优抽成计算,实现对优秀陪玩师的激励和对服务质量的管控,从而提升平台整体服务水平和陪玩师积极性。

## 术语表

- **系统**: 指 GameLink 陪玩管理平台的陪玩师绩效与动态抽成模块
- **管理员**: 具有配置抽成规则和查看绩效数据权限的平台管理人员
- **陪玩师**: 在平台上提供陪玩服务的专业服务人员
- **抽成比例**: 平台从陪玩师订单收入中抽取的佣金百分比
- **全站排名抽成**: 根据陪玩师在平台的综合排名设置的抽成比例
- **个人签约抽成**: 与平台签约的陪玩师享有的特殊抽成比例
- **服务项目抽成**: 针对特定服务项目设置的抽成比例
- **最低抽成原则**: 当多个抽成规则同时适用时,选择抽成比例最低的规则
- **综合排名**: 基于订单量、评分、服务时长等多维度指标计算的陪玩师排名
- **签约陪玩师**: 与平台签订特殊合作协议的陪玩师
- **抽成规则**: 定义抽成比例计算方式的配置规则
- **绩效指标**: 用于计算陪玩师排名的评估指标
- **抽成历史**: 陪玩师历史订单的抽成记录

## 需求

### 需求 1

**用户故事:** 作为管理员,我希望配置全站排名抽成规则,以便激励表现优秀的陪玩师。

#### 验收标准

1. WHEN 管理员创建排名抽成规则 THEN 系统应支持设置排名区间和对应的抽成比例
2. WHEN 管理员设置排名规则 THEN 系统应支持配置第1名10%、第2名15%等递增抽成比例
3. WHEN 管理员修改排名规则 THEN 系统应立即应用新规则到后续订单的抽成计算
4. WHEN 系统计算排名 THEN 系统应基于订单量、评分、服务时长等多维度指标综合排名
5. WHEN 管理员查看排名规则 THEN 系统应展示当前生效的所有排名区间和抽成比例

### 需求 2

**用户故事:** 作为管理员,我希望为签约陪玩师设置个人抽成,以便提供差异化的激励政策。

#### 验收标准

1. WHEN 管理员设置个人抽成 THEN 系统应支持为指定陪玩师配置专属抽成比例
2. WHEN 管理员创建签约协议 THEN 系统应记录签约陪玩师的抽成比例和生效时间
3. WHEN 签约协议到期 THEN 系统应自动停用个人抽成并恢复默认抽成规则
4. WHEN 管理员修改个人抽成 THEN 系统应记录修改历史和修改原因
5. WHEN 管理员查看签约列表 THEN 系统应展示所有签约陪玩师及其抽成比例

### 需求 3

**用户故事:** 作为管理员,我希望配置服务项目抽成,以便根据不同服务类型调整抽成策略。

#### 验收标准

1. WHEN 管理员设置项目抽成 THEN 系统应支持为每个服务项目配置抽成比例
2. WHEN 管理员创建服务项目 THEN 系统应要求设置该项目的默认抽成比例
3. WHEN 管理员修改项目抽成 THEN 系统应立即应用到该项目的后续订单
4. WHEN 管理员批量设置 THEN 系统应支持按游戏或服务类别批量配置抽成比例
5. WHEN 管理员查看项目抽成 THEN 系统应展示所有服务项目及其抽成比例

### 需求 4

**用户故事:** 作为管理员,我希望系统自动选择最低抽成,以便给予陪玩师最优惠的抽成比例。

#### 验收标准

1. WHEN 订单创建时 THEN 系统应计算全站排名抽成、个人签约抽成和服务项目抽成三个值
2. WHEN 系统选择抽成 THEN 系统应从三个抽成比例中选择数值最低的一个
3. WHEN 抽成规则冲突 THEN 系统应优先应用对陪玩师最有利的抽成比例
4. WHEN 订单结算时 THEN 系统应使用订单创建时确定的抽成比例进行结算
5. WHEN 管理员查看抽成详情 THEN 系统应展示订单使用的抽成比例和选择原因

### 需求 5

**用户故事:** 作为管理员,我希望计算陪玩师的综合排名,以便确定其适用的排名抽成。

#### 验收标准

1. WHEN 系统计算排名 THEN 系统应综合考虑订单量、评分、服务时长和用户满意度
2. WHEN 管理员配置排名权重 THEN 系统应支持调整各项指标在排名计算中的权重
3. WHEN 排名数据更新 THEN 系统应每日自动重新计算所有陪玩师的排名
4. WHEN 管理员查看排名 THEN 系统应展示陪玩师的当前排名和各项指标得分
5. WHEN 排名发生变化 THEN 系统应记录排名变更历史和变更时间

### 需求 6

**用户故事:** 作为管理员,我希望查看抽成历史记录,以便审计和分析抽成数据。

#### 验收标准

1. WHEN 管理员查看抽成历史 THEN 系统应展示每笔订单的抽成比例和抽成金额
2. WHEN 管理员筛选记录 THEN 系统应支持按陪玩师、时间范围、抽成类型筛选
3. WHEN 管理员查看统计 THEN 系统应展示总抽成金额和平均抽成比例
4. WHEN 管理员导出数据 THEN 系统应支持导出抽成历史记录为 Excel 格式
5. WHEN 订单完成结算 THEN 系统应记录该订单的抽成详情到历史记录

### 需求 7

**用户故事:** 作为管理员,我希望设置抽成规则的生效时间,以便灵活控制规则的应用时机。

#### 验收标准

1. WHEN 管理员创建抽成规则 THEN 系统应支持设置规则的生效开始时间和结束时间
2. WHEN 规则生效时间到达 THEN 系统应自动启用该抽成规则
3. WHEN 规则结束时间到达 THEN 系统应自动停用该抽成规则
4. WHEN 多个规则同时生效 THEN 系统应按照最低抽成原则选择适用规则
5. WHEN 管理员查看规则状态 THEN 系统应展示规则的生效状态和剩余有效期

### 需求 8

**用户故事:** 作为管理员,我希望模拟抽成计算,以便在应用规则前验证其效果。

#### 验收标准

1. WHEN 管理员使用模拟功能 THEN 系统应支持输入陪玩师和订单信息进行抽成计算
2. WHEN 系统模拟计算 THEN 系统应展示三种抽成规则的计算结果和最终选择
3. WHEN 管理员批量模拟 THEN 系统应支持上传陪玩师列表进行批量抽成模拟
4. WHEN 模拟结果生成 THEN 系统应展示每个陪玩师的抽成比例和预估抽成金额
5. WHEN 管理员导出模拟结果 THEN 系统应支持导出模拟数据为 Excel 格式

### 需求 9

**用户故事:** 作为管理员,我希望查看抽成规则的影响分析,以便评估规则的激励效果。

#### 验收标准

1. WHEN 管理员查看影响分析 THEN 系统应展示规则实施前后的订单量和收入变化
2. WHEN 系统分析效果 THEN 系统应计算规则对陪玩师活跃度和用户满意度的影响
3. WHEN 管理员对比规则 THEN 系统应支持对比不同抽成规则的效果差异
4. WHEN 管理员查看受益陪玩师 THEN 系统应展示因规则调整而降低抽成的陪玩师列表
5. WHEN 管理员生成分析报告 THEN 系统应支持导出抽成规则影响分析报告

### 需求 10

**用户故事:** 作为管理员,我希望设置抽成规则的优先级,以便在复杂场景下控制规则的应用顺序。

#### 验收标准

1. WHEN 管理员配置优先级 THEN 系统应支持为每个抽成规则设置优先级数值
2. WHEN 系统选择规则 THEN 系统应在最低抽成原则的基础上考虑规则优先级
3. WHEN 抽成比例相同 THEN 系统应选择优先级更高的规则
4. WHEN 管理员调整优先级 THEN 系统应立即应用新的优先级顺序
5. WHEN 管理员查看规则列表 THEN 系统应按优先级顺序展示所有抽成规则
