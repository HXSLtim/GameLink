# 需求文档 - RBAC 按钮级权限管理模块

## 简介

本文档定义了 GameLink 陪玩管理平台的 RBAC（基于角色的访问控制）按钮级权限管理模块的功能需求。该模块在现有权限系统基础上，实现精确到按钮级别的权限控制，包括权限定义、角色权限分配、前端权限渲染、后端权限验证等完整功能链路。

## 术语表

- **系统 (System)**: GameLink 陪玩管理平台的权限管理系统
- **管理员 (Administrator)**: 具有权限管理功能的平台管理人员
- **权限 (Permission)**: 对特定资源或操作的访问控制标识，格式为 `模块.资源.操作`（如 `admin.users.create`）
- **角色 (Role)**: 一组权限的集合，可分配给用户
- **按钮级权限 (Button-Level Permission)**: 精确控制页面中每个操作按钮的显示/隐藏或启用/禁用
- **权限码 (Permission Code)**: 权限的唯一语义化标识符
- **权限组 (Permission Group)**: 按功能模块分组的权限集合
- **超级管理员 (Super Admin)**: 拥有所有权限的特殊角色

## 需求

### 需求 1：权限定义与管理

**用户故事：** 作为超级管理员，我想要定义和管理系统中的所有权限，以便建立完整的权限体系。

#### 验收标准

1. WHEN 管理员访问权限管理页面 THEN 系统 SHALL 显示所有权限列表，包括权限码、描述、所属分组和关联的 API 路径
2. WHEN 管理员创建新权限 THEN 系统 SHALL 要求输入权限码（格式：模块.资源.操作）、描述、分组和关联的 HTTP 方法与路径
3. WHEN 管理员输入的权限码格式不符合规范 THEN 系统 SHALL 显示格式错误提示并阻止保存
4. WHEN 管理员编辑权限 THEN 系统 SHALL 允许修改描述和分组，但权限码创建后不可修改
5. WHEN 管理员删除权限 THEN 系统 SHALL 检查该权限是否被角色引用，如被引用则显示警告并要求确认

### 需求 2：角色权限分配

**用户故事：** 作为超级管理员，我想要为不同角色分配精确的按钮级权限，以便实现细粒度的访问控制。

#### 验收标准

1. WHEN 管理员访问角色权限配置页面 THEN 系统 SHALL 以树形结构展示所有权限，按模块和资源分组
2. WHEN 管理员为角色勾选权限 THEN 系统 SHALL 支持批量选择（选中父节点自动选中所有子节点）
3. WHEN 管理员保存角色权限 THEN 系统 SHALL 更新角色的权限关联并立即生效
4. WHEN 管理员查看角色已有权限 THEN 系统 SHALL 高亮显示已分配的权限项
5. WHEN 管理员为系统角色（superAdmin）配置权限 THEN 系统 SHALL 显示提示说明超级管理员默认拥有所有权限

### 需求 3：前端按钮权限渲染

**用户故事：** 作为前端开发者，我想要使用统一的权限组件控制按钮显示，以便实现一致的权限控制体验。

#### 验收标准

1. WHEN 用户访问包含权限控制按钮的页面 THEN 系统 SHALL 根据用户权限决定按钮的显示或隐藏
2. WHEN 用户无某按钮权限且配置为禁用模式 THEN 系统 SHALL 显示禁用状态的按钮并提供无权限提示
3. WHEN 用户权限数据加载中 THEN 系统 SHALL 显示加载状态，避免权限闪烁
4. WHEN 页面需要检查多个权限 THEN 系统 SHALL 支持 any（任一满足）和 all（全部满足）两种模式
5. WHEN 用户为超级管理员 THEN 系统 SHALL 显示所有按钮，无需逐一检查权限

### 需求 4：后端 API 权限验证

**用户故事：** 作为后端开发者，我想要在 API 层面验证用户权限，以便确保即使前端被绕过也能保证安全。

#### 验收标准

1. WHEN 用户请求受保护的 API THEN 系统 SHALL 验证用户是否拥有该 API 对应的权限
2. WHEN 用户权限验证失败 THEN 系统 SHALL 返回 403 状态码和标准化的错误响应
3. WHEN API 需要多个权限 THEN 系统 SHALL 支持配置权限检查模式（any 或 all）
4. WHEN 超级管理员请求任何 API THEN 系统 SHALL 跳过权限检查直接放行
5. WHEN 权限验证发生错误 THEN 系统 SHALL 记录错误日志并返回 500 状态码

### 需求 5：权限数据同步

**用户故事：** 作为用户，我想要在权限变更后立即生效，以便获得最新的访问权限。

#### 验收标准

1. WHEN 管理员修改用户角色 THEN 系统 SHALL 在用户下次请求时使用新权限
2. WHEN 管理员修改角色权限 THEN 系统 SHALL 使该角色所有用户的权限缓存失效
3. WHEN 用户登录 THEN 系统 SHALL 返回用户的完整权限列表
4. WHEN 前端检测到权限变更 THEN 系统 SHALL 自动刷新权限数据
5. WHEN 权限缓存过期 THEN 系统 SHALL 重新从数据库加载权限数据

### 需求 6：权限审计日志

**用户故事：** 作为安全管理员，我想要查看权限变更的审计日志，以便追踪权限操作历史。

#### 验收标准

1. WHEN 管理员修改角色权限 THEN 系统 SHALL 记录操作者、操作时间、变更前后的权限差异
2. WHEN 管理员修改用户角色 THEN 系统 SHALL 记录操作者、操作时间、变更前后的角色
3. WHEN 管理员查看审计日志 THEN 系统 SHALL 支持按时间范围、操作类型、操作者筛选
4. WHEN 审计日志超过保留期限 THEN 系统 SHALL 自动归档而非删除
5. WHEN 管理员导出审计日志 THEN 系统 SHALL 生成包含完整操作记录的 CSV 文件

### 需求 7：权限模板管理

**用户故事：** 作为管理员，我想要使用权限模板快速创建角色，以便提高角色配置效率。

#### 验收标准

1. WHEN 管理员访问权限模板页面 THEN 系统 SHALL 显示预定义的权限模板列表（如：内容管理员、财务管理员、客服专员）
2. WHEN 管理员基于模板创建角色 THEN 系统 SHALL 自动填充模板中定义的权限
3. WHEN 管理员保存当前角色为模板 THEN 系统 SHALL 创建新的权限模板
4. WHEN 管理员编辑权限模板 THEN 系统 SHALL 允许修改模板名称、描述和包含的权限
5. WHEN 管理员删除权限模板 THEN 系统 SHALL 检查是否有角色基于该模板创建，如有则显示警告

### 需求 8：菜单权限联动

**用户故事：** 作为用户，我想要只看到我有权限访问的菜单，以便获得清晰的导航体验。

#### 验收标准

1. WHEN 用户登录后访问管理后台 THEN 系统 SHALL 只显示用户有权限访问的菜单项
2. WHEN 用户无某菜单下所有按钮权限 THEN 系统 SHALL 隐藏该菜单项
3. WHEN 用户直接访问无权限的页面 URL THEN 系统 SHALL 重定向到 403 页面
4. WHEN 菜单权限配置变更 THEN 系统 SHALL 动态更新侧边栏菜单显示
5. WHEN 用户拥有子菜单权限但无父菜单权限 THEN 系统 SHALL 显示父菜单但禁用其直接访问

### 需求 9：批量权限操作

**用户故事：** 作为管理员，我想要批量管理用户权限，以便高效处理大量用户的权限配置。

#### 验收标准

1. WHEN 管理员选择多个用户 THEN 系统 SHALL 提供批量分配角色的功能
2. WHEN 管理员批量分配角色 THEN 系统 SHALL 显示操作预览，包括将受影响的用户数量
3. WHEN 批量操作完成 THEN 系统 SHALL 显示操作结果摘要，包括成功和失败的数量
4. WHEN 批量操作部分失败 THEN 系统 SHALL 显示失败的用户列表和失败原因
5. WHEN 管理员撤销批量操作 THEN 系统 SHALL 支持在操作后 5 分钟内撤销

### 需求 10：权限继承与覆盖

**用户故事：** 作为管理员，我想要配置权限的继承关系，以便简化复杂的权限配置。

#### 验收标准

1. WHEN 用户拥有多个角色 THEN 系统 SHALL 合并所有角色的权限（并集）
2. WHEN 角色配置了权限继承 THEN 系统 SHALL 自动包含父角色的所有权限
3. WHEN 管理员查看用户有效权限 THEN 系统 SHALL 显示合并后的完整权限列表及来源
4. WHEN 权限存在冲突（如显式拒绝）THEN 系统 SHALL 按照拒绝优先的原则处理
5. WHEN 管理员配置角色继承关系 THEN 系统 SHALL 检测并阻止循环继承
