## 📋 改进原则

### 1. 测试文件命名规范
**当前问题**: 
- 存在 `*_quick_test.go`, `*_badjson_test.go`, `*_invalid_test.go` 等多种命名
- 不符合 Go 标准测试命名规范

**改进目标**:
- 所有测试文件统一命名为 `*_test.go`
- 不同类型的测试用例放在同一个测试文件中，使用 TestXXX 区分
- 例如：`order_test.go` 包含所有订单测试（正常、边界、快速等）

**命名对照表**:
```
order_test.go                    ← order_quick_test.go
                                 ← order_badjson_test.go
                                 ← order_invalid_test.go
                                 
commission_test.go               ← commission_handler_quick_test.go
                                 ← commission_complete_test.go
                                 
player_test.go                   ← player_basic_test.go
                                 ← player_extended_test.go
```

## 📝 注意事项

### 测试文件合并原则
1. **不删除测试用例**: 合并时保留所有测试逻辑
2. **使用子测试**: 使用 `t.Run()` 组织不同类型的测试
3. **示例结构**:
```go
func TestOrderService(t *testing.T) {
    t.Run("CreateOrder", func(t *testing.T) {
        // 正常创建测试
    })
    
    t.Run("CreateOrder_InvalidInput", func(t *testing.T) {
        // 无效输入测试（原 badjson/invalid）
    })
    
    t.Run("CreateOrder_Quick", func(t *testing.T) {
        // 快速测试（原 quick）
    })
}
```

### 接口改动测试要求
1. **任何接口改动必须写测试**
2. **新增接口必须100%测试覆盖**
3. **修改接口必须保证原有测试通过**
4. **删除接口必须删除对应测试**

### 代码审查要求
1. **每个TODO任务完成后必须Code Review**
2. **测试代码必须Review**
3. **确保测试命名规范**
