# GameLink 项目 Code Review 标准

**制定时间**: 2025-11-22
**适用范围**: 全项目代码审查

---

## 🎯 Review 维度

### 1. 代码规范性 (25分)
- [ ] 遵循 Go 编码规范 (gofmt, goimports)
- [ ] 命名清晰，符合惯例
- [ ] 注释完整，函数有文档
- [ ] 错误处理规范
- [ ] 无冗余代码

### 2. 架构设计 (25分)
- [ ] 符合 Clean Architecture 分层
- [ ] 依赖关系正确 (内层不依赖外层)
- [ ] 接口抽象合理
- [ ] 单一职责原则
- [ ] 开闭原则

### 3. 代码质量 (20分)
- [ ] 无重复代码 (DRY)
- [ ] 函数长度适中 (<50行)
- [ ] 圈复杂度合理 (<15)
- [ ] 资源正确释放 (defer)
- [ ] 线程安全

### 4. 安全性 (15分)
- [ ] 无 SQL 注入风险
- [ ] 无 XSS 风险
- [ ] 敏感信息保护
- [ ] 输入验证
- [ ] 权限控制

### 5. 可维护性 (15分)
- [ ] 测试覆盖充分
- [ ] 日志完善
- [ ] 配置化
- [ ] 易于扩展
- [ ] 文档清晰

---

## 📋 分层 Review 清单

### Model 层检查项
- [ ] 数据结构合理
- [ ] GORM 标签正确
- [ ] JSON 序列化标签正确
- [ ] 自定义类型实现必要接口 (Scanner/Valuer)
- [ ] 表关系定义正确
- [ ] 索引设置合理
- [ ] 软删除配置
- [ ] 无业务逻辑

### Repository 层检查项
- [ ] 接口定义在 repository/interfaces/
- [ ] 实现放在对应模块目录
- [ ] 事务处理正确
- [ ] 查询优化 (N+1问题)
- [ ] 错误处理完整
- [ ] 无业务逻辑
- [ ] 支持上下文取消

### Service 层检查项
- [ ] 业务逻辑完整
- [ ] 事务边界合理
- [ ] 权限检查
- [ ] 数据验证
- [ ] 事件发布
- [ ] 无 HTTP 依赖
- [ ] 可测试性

### Handler 层检查项
- [ ] 路由定义清晰
- [ ] 请求验证
- [ ] 错误响应规范
- [ ] 状态码正确
- [ ] 中间件使用正确
- [ ] 无业务逻辑
- [ ] Swagger 文档完整

---

## 🚨 严重问题定义

### 🔴 严重 (必须修复)
- 安全漏洞 (SQL注入、XSS等)
- 数据竞争
- 资源泄漏
- 事务未正确处理
- 权限绕过

### 🟡 重要 (建议修复)
- 代码重复 > 3处
- 函数过长 (>100行)
- 圈复杂度 > 20
- 缺少错误处理
- 测试覆盖 < 60%

### 🟢 一般 (可选修复)
- 命名不够清晰
- 注释不完整
- 日志不够详细
- 代码风格问题

---

## 📊 评分标准

### 90-100分: 优秀
- 无严重问题
- 架构清晰
- 测试覆盖 > 80%
- 文档完善

### 80-89分: 良好
- 无严重问题
- 架构合理
- 测试覆盖 > 60%
- 基本文档

### 70-79分: 合格
- 无致命问题
- 架构基本合理
- 测试覆盖 > 40%

### < 70分: 需重构
- 存在严重问题
- 架构混乱
- 缺乏测试

## 🔧 Review 工具

### 自动化检查
```bash
# 代码规范
golangci-lint run

# 测试覆盖
go test -cover ./...

# 静态分析
go vet ./...

# 依赖检查
go mod verify
```

### 手动检查重点
- 业务逻辑正确性
- 边界条件处理
- 并发安全性
- 性能瓶颈

---

## 📝 Review 流程

1. **准备阶段**: 理解业务需求和设计
2. **代码阅读**: 从整体到局部
3. **问题记录**: 按严重程度分类
4. **反馈沟通**: 与作者讨论
5. **修复验证**: 确认问题已解决
6. **总结报告**: 生成 review 报告
