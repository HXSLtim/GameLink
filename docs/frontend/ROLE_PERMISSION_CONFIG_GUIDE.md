# 角色权限配置指南

本文档介绍 GameLink 平台角色权限配置的使用方法和最佳实践。

## 概述

角色权限配置功能允许管理员为不同角色分配精确的按钮级权限，实现细粒度的访问控制。

### 核心功能

1. **树形权限展示** - 按模块和资源分组展示所有权限
2. **父子节点联动** - 选中父节点自动选中所有子节点
3. **批量权限分配** - 支持全选/反选操作
4. **实时生效** - 保存后权限立即生效
5. **系统角色保护** - 超级管理员角色不可修改

## 访问路径

1. 登录管理后台
2. 进入 **系统管理** > **角色管理**
3. 点击角色列表中的 **配置权限** 按钮

或直接访问：`/admin/sys/role/:id/permissions`

## 权限配置界面

### 角色信息区域

显示当前配置的角色基本信息：

| 字段 | 说明 |
|------|------|
| 角色名称 | 角色的显示名称 |
| 角色编码 | 角色的唯一标识（slug） |
| 优先级 | 权限冲突时的优先级 |
| 描述 | 角色的功能描述 |
| 系统角色标签 | 标识是否为系统预设角色 |

### 权限树区域

权限以树形结构展示，按以下层级组织：

```
权限分组（如：用户管理）
├── 权限项（如：查看用户列表）
├── 权限项（如：创建用户）
├── 权限项（如：更新用户）
└── 权限项（如：删除用户）
```

#### 权限树功能

| 功能 | 说明 |
|------|------|
| 搜索 | 输入关键词快速定位权限 |
| 全选/反选 | 一键选中或取消所有权限 |
| 展开/收起 | 展开或收起权限分组 |
| 虚拟滚动 | 大量权限时保持流畅性能 |

## 操作指南

### 1. 选择权限

**单个权限选择：**
- 点击权限项前的复选框选中/取消

**批量选择：**
- 选中父节点（分组）自动选中所有子权限
- 取消父节点自动取消所有子权限
- 使用"全选"按钮选中所有权限

**搜索定位：**
- 在搜索框输入权限名称或描述
- 匹配的权限会高亮显示

### 2. 保存配置

1. 完成权限选择后，点击 **保存配置** 按钮
2. 系统会显示保存成功提示
3. 权限变更立即生效，相关用户的缓存会自动失效

### 3. 重置配置

如果需要撤销未保存的更改：
- 点击 **重置** 按钮恢复到上次保存的状态

### 4. 返回列表

- 点击 **返回** 按钮回到角色列表
- 如有未保存的更改，系统会提示确认

## 特殊角色说明

### 超级管理员（superAdmin）

超级管理员是系统最高权限角色：

- **自动拥有所有权限**：无需单独配置
- **权限检查跳过**：系统自动放行所有操作
- **配置面板只读**：无法修改权限配置

> 💡 如需限制某些管理员的权限，请创建新的自定义角色，而不是修改超级管理员。

### 系统预设角色

系统预设角色（如 admin、player、user）：

- 可以修改权限配置
- 修改时会显示警告提示
- 建议谨慎修改，避免影响系统正常运行

## 最佳实践

### 1. 最小权限原则

只分配角色实际需要的权限，避免过度授权：

```
✅ 客服角色：查看用户、查看订单、处理纠纷
❌ 客服角色：删除用户、删除订单、系统配置
```

### 2. 按职责划分角色

根据实际工作职责创建角色：

| 角色 | 建议权限 |
|------|---------|
| 内容审核员 | 评价管理、动态管理、举报管理 |
| 财务管理员 | 支付管理、提现管理、佣金管理 |
| 客服专员 | 用户管理（只读）、订单管理（只读）、纠纷管理 |
| 运营管理员 | 游戏管理、陪玩师管理、统计数据 |

### 3. 定期审查权限

- 定期检查角色权限配置是否合理
- 员工离职或转岗时及时调整角色
- 使用审计日志追踪权限变更

### 4. 使用角色继承

如果多个角色有相似权限，可以：
1. 创建基础角色包含公共权限
2. 子角色继承父角色权限
3. 子角色添加额外权限

## API 接口

### 获取角色权限

```http
GET /api/v1/admin/roles/:id/permissions
```

返回角色已分配的权限 ID 列表。

### 批量分配权限

```http
PUT /api/v1/admin/roles/:id/permissions/batch
Content-Type: application/json

{
    "permissionIds": [1, 2, 3, 4, 5]
}
```

替换角色的所有权限（事务保证原子性）。

### 添加单个权限

```http
POST /api/v1/admin/roles/:id/permissions/:pid
```

为角色添加单个权限。

### 移除单个权限

```http
DELETE /api/v1/admin/roles/:id/permissions/:pid
```

从角色移除单个权限。

### 获取权限树

```http
GET /api/v1/admin/permissions/tree
```

返回按父子关系组织的权限树形结构。

## 常见问题

### Q: 修改权限后多久生效？

A: 权限变更立即生效。系统会自动失效相关用户的权限缓存，用户下次请求时会使用新权限。

### Q: 为什么无法修改超级管理员权限？

A: 超级管理员是系统最高权限角色，自动拥有所有权限，无需单独配置。如需限制权限，请创建新角色。

### Q: 如何查看权限变更历史？

A: 进入 **系统管理** > **审计日志**，筛选"角色权限变更"类型的日志。

### Q: 权限配置后用户看不到菜单？

A: 检查以下几点：
1. 用户是否已分配该角色
2. 角色是否已分配相关权限
3. 用户是否需要重新登录刷新权限

### Q: 如何批量为多个角色配置相同权限？

A: 目前需要逐个配置。建议：
1. 创建一个模板角色
2. 配置好权限
3. 基于模板创建新角色（继承权限）
