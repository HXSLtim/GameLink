# 三端 MVP 最小回滚清单

## 1. 触发条件（任一满足即回滚）
- 发布工作流出现阻断失败且 15 分钟内无法恢复。
- 核心链路异常：登录、下单、支付、提现任一关键指标持续异常。
- 健康检查失败：后端健康接口或前端可达性连续失败。

## 2. 回滚分工
- Commander：宣布回滚、冻结新变更、同步通知。
- API Owner：回滚后端镜像/服务，确认数据库与缓存一致性。
- Admin Owner：回滚管理端静态资源与配置。
- App Owner：回滚用户端静态资源与环境变量。
- QA/SRE：验证回滚结果并归档事故时间线。

## 3. 最小回滚动作（按端）

### 3.1 API 端
- 选择上一个稳定版本镜像（上一成功发布 tag）。
- 回滚 API 服务并检查 `/api/v1/healthz`。
- 执行关键回归：`run_flow_guard_regression.ps1`（必要时）。

### 3.2 Admin 端
- 回滚到上一稳定前端镜像/构建产物。
- 验证登录、用户管理、订单管理主页面可用。

### 3.3 App 端
- 回滚到上一稳定前端构建产物。
- 验证用户主路径：登录、陪玩列表、订单、钱包。

## 4. 回滚后验证（必须）
- 后端健康检查 PASS。
- `mvp-three-end-release-report` 与工程验收报告无新增失败项。
- 业务关键指标恢复到阈值内（错误率/可用性/响应时间）。

## 5. 事故后动作
- 30 分钟内产出初步结论（影响范围 + 临时修复）。
- 24 小时内完成复盘（根因、改进项、负责人、截止时间）。
