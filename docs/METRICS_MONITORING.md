## 📊 数据埋点方案

### 埋点原则

1. **最小必要**: 只埋必要的数据点
2. **用户隐私**: 不收集敏感个人信息
3. **性能优先**: 不影响用户体验
4. **实时优先**: 关键指标实时上报

### 埋点技术栈

**前端埋点**:
- Admin: 自研埋点SDK + Mixpanel
- Mobile: uni-app 统计 + 友盟统计

**后端埋点**:
- API日志: ELK Stack（Elasticsearch + Logstash + Kibana）
- 数据库: PostgreSQL + TimescaleDB

**数据存储**:
- 实时数据: Redis
- 时序数据: InfluxDB
- 分析数据: ClickHouse

### 埋点事件定义

#### 用户行为事件

| 事件名称 | 触发时机 | 参数 | 优先级 |
|---------|---------|------|--------|
| `app_start` | APP启动 | device_id, app_version | P0 |
| `page_view` | 页面浏览 | page_name, referrer | P0 |
| `user_login` | 用户登录 | user_id, login_method | P0 |
| `user_register` | 用户注册 | user_id, register_method | P0 |
| `user_logout` | 用户登出 | user_id | P1 |

#### 业务行为事件

| 事件名称 | 触发时机 | 参数 | 优先级 |
|---------|---------|------|--------|
| `player_view` | 查看陪玩详情 | user_id, player_id | P0 |
| `player_search` | 搜索陪玩 | user_id, keyword | P0 |
| `player_filter` | 筛选陪玩 | user_id, filters | P1 |
| `order_create` | 创建订单 | user_id, order_amount | P0 |
| `order_pay` | 发起支付 | user_id, payment_method | P0 |
| `order_complete` | 订单完成 | user_id, order_id | P0 |
| `order_cancel` | 订单取消 | user_id, cancel_reason | P0 |

#### 交互行为事件

| 事件名称 | 触发时机 | 参数 | 优先级 |
|---------|---------|------|--------|
| `chat_send` | 发送消息 | user_id, message_type | P0 |
| `player_favorite` | 收藏陪玩 | user_id, player_id | P1 |
| `coupon_receive` | 领取优惠券 | user_id, coupon_id | P1 |
| `vip_purchase` | 购买会员 | user_id, vip_level | P1 |

### 埋点实现示例

**前端埋点（Admin）**:
```typescript
// 埋点SDK初始化
import Analytics from 'analytics-sdk';

Analytics.init({
  projectId: 'gamelink-admin',
  endpoint: '/api/v1/analytics/events',
  autoTrack: true,
});

// 自定义事件埋点
Analytics.track('player_view', {
  player_id: '12345',
  player_name: '游戏大神',
  game: '王者荣耀',
  price: 30,
});
```

**移动端埋点（App）**:
```typescript
// uni-app 统计
import analytics from '@/utils/analytics';

analytics.track('order_create', {
  player_id: '12345',
  order_amount: 30,
  payment_method: 'wechat',
});
```

**后端埋点（API）**:
```go
// API请求埋点
func AnalyticsMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()

        c.Next()

        duration := time.Since(start)
        analytics.RecordAPIRequest(analytics.APIRequest{
            Path:       c.Request.URL.Path,
            Method:     c.Request.Method,
            StatusCode: c.Writer.Status(),
            Duration:   duration,
            UserID:     c.GetString("user_id"),
        })
    }
}
```

## 🛠️ 分析平台选型

### 平台对比

| 平台 | 优势 | 劣势 | 价格 | 推荐度 |
|------|------|------|------|--------|
| **Google Analytics** | 免费、功能强大 | 国内访问慢 | 免费 | ⭐⭐⭐⭐ |
| **Mixpanel** | 事件分析强 | 价格高 | $25/月 | ⭐⭐⭐⭐⭐ |
| **友盟统计** | 国内稳定、免费 | 功能有限 | 免费 | ⭐⭐⭐⭐ |
| **神策数据** | 私有化部署 | 价格高 | 联系销售 | ⭐⭐⭐ |
| **自研平台** | 完全定制 | 开发成本高 | 开发成本 | ⭐⭐⭐ |

### 推荐方案

**阶段1（MVP - 3个月）**:
- ✅ Google Analytics（基础分析）
- ✅ 友盟统计（移动端）
- ✅ 自研简单Dashboard（关键指标）

**阶段2（增长期 - 6个月）**:
- ✅ Mixpanel（事件分析）
- ✅ 自研数据平台（深度分析）
- ✅ A/B测试平台

**阶段3（成熟期 - 12个月）**:
- ✅ 完整自研数据平台
- ✅ 实时数据大屏
- ✅ AI预测分析

## 📈 数据分析流程

### 1. 数据收集

**实时数据**:
- 用户登录/登出
- 订单创建/支付/完成
- API请求/响应
- WebSocket连接

**批量数据**:
- 用户注册信息
- 陪玩认证信息
- 订单详细数据
- 评价数据

### 2. 数据处理

**实时处理**（流式）:
- 工具: Kafka + Flink
- 用途: 实时监控、告警

**批量处理**（离线）:
- 工具: Airflow + Spark
- 用途: 日报、周报、月报

### 3. 数据存储

**热数据**（Redis）:
- 实时在线用户
- 实时订单统计
- 实时聊天消息

**温数据**（PostgreSQL）:
- 用户基本信息
- 订单基本信息
- 业务数据

**冷数据**（ClickHouse）:
- 历史埋点数据
- 历史日志数据
- 分析数据

### 4. 数据分析

**描述性分析**（发生了什么）:
- DAU、MAU趋势
- 订单量变化
- 收入增长情况

**诊断性分析**（为什么发生）:
- 用户流失原因
- 订单取消原因
- 支付失败原因

**预测性分析**（将要发生什么）:
- 用户流失预测
- 收入预测
- 订单量预测

**规范性分析**（应该做什么）:
- 推荐算法优化
- 运营策略调整
- 产品迭代方向

## 🚨 告警机制

### 告警规则

| 指标 | 阈值 | 级别 | 通知方式 |
|------|------|------|---------|
| API错误率 | >5% | P0 | 短信+电话 |
| API响应时间 | >2秒 | P1 | 短信 |
| 支付成功率 | <90% | P0 | 短信+电话 |
| WebSocket连接率 | <90% | P1 | 短信 |
| DAU下降 | >20% | P1 | 邮件+企业微信 |
| 订单量下降 | >30% | P0 | 短信+电话 |

### 告警流程

1. **触发告警**: 系统检测到异常
2. **发送通知**: 发送给相关负责人
3. **问题确认**: 运维人员确认问题
4. **问题处理**: 技术团队处理问题
5. **问题恢复**: 系统恢复正常
6. **复盘分析**: 分析原因，优化流程
