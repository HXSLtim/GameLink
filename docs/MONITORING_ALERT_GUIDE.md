## 告警规则

### P0 - 严重告警

**需要立即处理，影响所有用户**

| 规则 | 触发条件 | 通知方式 | 响应时间 |
|------|---------|---------|---------|
| **服务完全不可用** | 所有容器 down | 电话 + 短信 + 邮件 | 5 分钟内 |
| **数据库连接失败** | 无法连接数据库 | 电话 + 短信 + 邮件 | 5 分钟内 |
| **磁盘空间不足** | 磁盘使用率 > 95% | 电话 + 短信 + 邮件 | 15 分钟内 |
| **错误率过高** | 错误率 > 10% | 短信 + 邮件 | 15 分钟内 |
| **响应时间过长** | P95 > 2000ms | 短信 + 邮件 | 15 分钟内 |

### P1 - 重要告警

**需要尽快处理，影响部分用户**

| 规则 | 触发条件 | 通知方式 | 响应时间 |
|------|---------|---------|---------|
| **服务重启频繁** | 容器重启 > 5 次 | 邮件 + IM | 30 分钟内 |
| **API 错误率上升** | 错误率 > 5% | 邮件 + IM | 30 分钟内 |
| **响应时间变慢** | P95 > 500ms | 邮件 + IM | 1 小时内 |
| **数据库慢查询** | 慢查询 > 50 | 邮件 + IM | 1 小时内 |
| **内存使用过高** | 内存使用率 > 85% | 邮件 + IM | 1 小时内 |
| **CPU 使用过高** | CPU 使用率 > 85% | 邮件 + IM | 1 小时内 |

### P2 - 一般告警

**可以计划处理，不影响用户**

| 规则 | 触发条件 | 通知方式 | 响应时间 |
|------|---------|---------|---------|
| **磁盘空间预警** | 磁盘使用率 > 85% | 邮件 | 1 个工作日内 |
| **连接数增长** | 连接数 > 正常值 50% | 邮件 | 1 个工作日内 |
| **日志错误增加** | 错误日志增长 > 50% | 邮件 | 1 个工作日内 |
| **缓存命中率下降** | 命中率 < 70% | 邮件 | 1 个工作日内 |

## 告警通道

### 邮件告警

**配置：**
```bash
# .env.production
ALERT_EMAIL_ENABLED=true
ALERT_EMAIL_TO=ops@gamelink.com,devops@gamelink.com
ALERT_EMAIL_FROM=noreply@gamelink.com
ALERT_EMAIL_SUBJECT="【GameLink 告警】%ENVIRONMENT% - %ALERT_NAME%"
```

**使用场景：**
- 所有 P1 和 P2 告警
- P0 告警的补充通知

### 即时消息告警

**配置：**
```bash
# 企业微信/钉钉/飞书
ALERT_IM_ENABLED=true
ALERT_IM_WEBHOOK=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx
```

**使用场景：**
- P1 告警
- P0 告警的快速通知

### 短信/电话告警

**配置：**
```bash
ALERT_SMS_ENABLED=true
ALERT_SMS_TO=+8613800138000
ALERT_CALL_ENABLED=false  # 极端情况启用
```

**使用场景：**
- 仅 P0 告警
- 确保关键问题能及时响应

## 故障排查

### 常见问题诊断流程

#### 问题 1：API 响应时间过长

**诊断步骤：**

1. **检查应用日志**
   ```bash
   bash scripts/collect-logs.sh production backend analyze
   ```

2. **检查数据库慢查询**
   ```bash
   docker exec gamelink-postgres psql \
     -U gamelink -d gamelink \
     -c "SELECT query, mean_exec_time FROM pg_stat_statements ORDER BY mean_exec_time DESC LIMIT 10;"
   ```

3. **检查缓存命中率**
   ```bash
   docker exec gamelink-redis redis-cli INFO stats | grep keyspace
   ```

4. **检查资源使用**
   ```bash
   bash scripts/monitor-app.sh production
   ```

**可能原因和解决方案：**

| 原因 | 解决方案 |
|------|---------|
| 数据库慢查询 | 优化查询，添加索引 |
| 缓存未命中 | 预热缓存，调整缓存策略 |
| 资源不足 | 扩展服务实例，增加资源 |
| 网络延迟 | 优化网络配置，使用 CDN |

#### 问题 2：错误率上升

**诊断步骤：**

1. **收集错误日志**
   ```bash
   bash scripts/collect-logs.sh production backend analyze | grep ERROR
   ```

2. **查看最近的部署**
   ```bash
   git log --oneline -10
   ```

3. **检查数据库状态**
   ```bash
   docker exec gamelink-postgres pg_isready -U gamelink
   ```

**可能原因和解决方案：**

| 原因 | 解决方案 |
|------|---------|
| 代码缺陷 | 回滚到稳定版本 |
| 数据库连接池耗尽 | 增加连接池大小 |
| 第三方服务故障 | 检查依赖服务，启用降级策略 |
| 配置错误 | 检查环境变量配置 |

#### 问题 3：内存使用过高

**诊断步骤：**

1. **检查内存使用**
   ```bash
   docker stats --no-stream
   ```

2. **分析内存泄漏**
   ```bash
   docker logs gamelink-backend | grep -i "memory\|leak"
   ```

3. **检查应用配置**
   ```bash
   docker inspect gamelink-backend | grep Memory
   ```

**可能原因和解决方案：**

| 原因 | 解决方案 |
|------|---------|
| 内存泄漏 | 重启服务，排查代码 |
| 连接未释放 | 检查连接池配置 |
| 缓存过大 | 限制缓存大小 |
| 日志过多 | 调整日志级别，定期清理 |

#### 问题 4：磁盘空间不足

**诊断步骤：**

1. **检查磁盘使用**
   ```bash
   df -h
   docker system df
   ```

2. **查找大文件**
   ```bash
   find /var/log -type f -size +100M -exec ls -lh {} \;
   ```

**解决方案：**

```bash
# 清理 Docker 未使用的资源
docker system prune -a

# 清理应用日志
bash scripts/collect-logs.sh production all clean

# 清理数据库日志
docker exec gamelink-postgres sh -c "rm -f /var/log/postgresql/*.log*"
```
