# 客户优先级文档（Must / Need / Not-Need）

## 1. 文档目标
- 基于 `docs/PRD.md`（SSOT）、`docs/USER_PERSONAS.md`、`docs/USER_RESEARCH_PLAN.md`、`docs/FEATURE_PRIORITIZATION.md`、`docs/PRODUCT_ROADMAP.md`，形成面向客户价值的功能优先级分层。
- 用于迭代排期、资源投入和验收门禁，避免范围失控与“先做锦上添花”。

## 2. 文档盘点与归类结果（摘要）

### 2.1 核心事实源（产品与客户）
- `docs/PRD.md`：功能范围、优先级（P0/P1/P2）、核心角色与验收基线。
- `docs/USER_PERSONAS.md`：客户细分、场景、痛点与消费行为。
- `docs/USER_RESEARCH_PLAN.md`：目标用户、决策因素与风险关注点（价格、质量、安全）。

### 2.2 规划与节奏（排期）
- `docs/FEATURE_PRIORITIZATION.md`：P0/P1/P2/P3 的功能优先级定义与迭代节奏。
- `docs/PRODUCT_ROADMAP.md`：v1.x-v3.x 里程碑节奏，验证短中长期投入边界。

### 2.3 扩展与实现参考
- `docs/PRD_COMPREHENSIVE.md`：扩展说明（参考版，非主事实源）。
- `docs/TASK_55_FUNCTIONALITY_LIST.md`：端侧实现状态与功能覆盖情况。
- 其他工程文档（架构、运维、测试、归档）作为“实现可行性与成本”参考，不直接决定客户优先级。

## 3. 主要客户与核心场景提取

### 3.1 主要客户
- 普通用户（主力人群）：目标是“快速匹配+稳定服务+价格透明+安全交易”。
- 技术提升型用户：目标是“高水平陪玩/教练+可衡量提升+高效时间利用”。
- VIP 用户：目标是“高质量服务+快速响应+尊贵体验”。
- 平台管理员（内部客户）：目标是“高效运营、风险控制、数据可见、流程可控”。

### 3.2 核心场景
- 场景A（高频主路径）：浏览陪玩师 → 创建订单 → 支付 → 实时聊天 → 服务完成 → 评价。
- 场景B（转化增益）：优惠券/会员权益驱动首单与复购。
- 场景C（服务保障）：争议处理、退款、客服介入、内容审核。
- 场景D（平台稳态）：管理后台对订单、用户、财务、风控进行实时管控。

## 4. Must / Need / Not-Need 功能清单

> 判定原则：
> - Must：不做会直接阻断交易闭环、信任闭环或合规闭环。
> - Need：显著提升增长、复购或运营效率，但不阻断基础交易。
> - Not-Need：当前阶段不影响闭环，属于增强或战略储备。

### 4.1 Must（必须有，优先投入）

#### 用户与交易闭环
- 用户注册登录与身份认证（含 Token 生命周期管理）。
- 陪玩师列表/详情、筛选与搜索。
- 创建订单、订单确认、支付（余额/微信/支付宝/组合支付）。
- 订单状态流转（待支付/进行中/已完成/取消/退款中）与订单详情。
- 评价系统（星级+文字+标签）。

#### 实时服务与履约
- WebSocket 实时聊天（消息收发、未读、断线重连）。
- 订单服务中的基本在线状态能力。

#### 资金与安全底座
- 钱包余额、充值、交易记录。
- 退款流程与支付回调稳定性。
- 内容审核、敏感词、举报处理（至少满足基础风控要求）。

#### 平台运营底座（管理端）
- 仪表盘、用户管理、订单管理、陪玩师审核。
- 财务关键链路：结算、提现审核、支付记录。
- RBAC 权限体系与实时监控。

### 4.2 Need（应该有，增长与效率）
- 陪玩师认证增强（实名/段位流程完善、结果反馈优化）。
- 优惠券系统（创建、发放、核销、过期）。
- VIP 体系（等级、权益、升级进度、折扣策略）。
- 推荐系统基础版（提升匹配效率与转化）。
- 推荐有礼/邀请奖励（拉新与裂变）。
- 数据分析与 KPI 仪表板（用于经营决策）。
- 设置、收藏、在线客服、帮助中心等体验强化模块。

### 4.3 Not-Need（当前阶段可延后）
- 语音房、视频陪玩。
- 礼物打赏、动态/社区 Feed、话题标签。
- 游戏战绩查询、攻略 Wiki、电竞赛事。
- 装备交易、培训学院、海外市场扩展。

## 5. 分阶段落地建议

### 5.1 阶段 1（MVP / v1.x）
- 只做 Must，验收目标聚焦：交易闭环可用、支付成功率、履约稳定性、风控可控。

### 5.2 阶段 2（增长期 / v2.x）
- 在 Must 稳定后迭代 Need，目标聚焦：转化率、复购率、留存率、运营效率。

### 5.3 阶段 3（战略扩展 / v3.x）
- 评估 Not-Need 的投入产出，再逐步上线高成本增强功能。

## 6. 维护规则
- 本文档为“客户价值优先级视图”，需求定义与范围变更仍以 `docs/PRD.md` 为准。
- 每次迭代规划前，先校准 Must/Need/Not-Need，再进入排期。
- 若某功能需提级（Need → Must），必须在 PRD 与本文件同步更新并记录原因。
